# 任务：全面 Docker 化

## 背景

LCAITool 项目需要完整的容器化部署方案，简化开发环境搭建和生产部署流程。参考 ADSpread 项目的成熟 Docker 化架构，为 LCAITool 实现完整的容器化方案。

## 目标

- 所有服务（后端、前端、Worker、数据库、缓存）Docker 化
- 使用 Nginx 作为统一网关，支持反向代理路由
- 开发环境一键启动，生产环境支持快速部署
- 数据持久化，健康检查，服务依赖链

## 范围

- 根目录 .dockerignore
- Backend Dockerfile (Python FastAPI)
- Frontend Admin Dockerfile + Nginx 配置 (React + Vite)
- Frontend User Dockerfile (Next.js)
- Gateway Nginx 配置
- Redis 配置
- docker-compose.yml 完整编排
- API 健康检查端点

## 非范围

- 不修改业务逻辑代码
- 不涉及 Kubernetes 编排
- 不修改 CI/CD 流水线配置

## 验证方式

```bash
# 验证 Compose 语法
docker compose config -q

# 构建所有镜像
docker compose build

# 启动基础服务验证
docker compose up postgres redis -d
sleep 10
docker compose ps

# 验证健康检查
docker compose exec postgres pg_isready -U lcaitool -d lcaitool
docker compose exec redis redis-cli ping

# 停止服务
docker compose down -v
```

## 备注

- 路由规则：用户端在 /，管理后台在 /admin/
- 使用多阶段构建优化镜像大小
- 参考 ADSpread 成熟架构实现
- PostgreSQL 升级至 18-alpine，volume 挂载点调整为 `/var/lib/postgresql`（适配 PG 18 新目录结构）
- 网关 Nginx 使用 `resolver 127.0.0.11 valid=30s` 动态 DNS 解析，容器重建后无需重启网关
- 数据同步时需注意：自定义 ENUM 类型（pointtransactiontype/orderstatus/paymentprovider/reconciliationstatus）需单独创建，sync_full.py 不会自动同步
- Celery `task_time_limit`/`task_soft_time_limit` 必须用单一数值或任务名作 key，用队列名作 key 会导致 billiard pool 崩溃
- Dev 模式下前端通过 Vite proxy / Next.js rewrites 转发 /api 到后端 :8000，不再直连后端端口
- 后端 .env 已指向 Docker PostgreSQL + Redis，dev 模式直接连接
