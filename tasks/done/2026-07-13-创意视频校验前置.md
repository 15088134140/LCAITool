# 任务：创意视频校验前置

## 背景

创意视频生成器在文生视频模式（未上传首帧/尾帧）下创意描述必填，但该校验只在 worker 的 `CreativeVideoExecutor._validate_params` 中进行。`create_task` 端点不校验参数，直接创建任务、冻结积分、提交 Celery，导致校验失败时前端无法在点击生成时即时提示，且 worker 的 `autoretry_for=(Exception,)` 会无意义重试 ValueError。

详见 `docs/superpowers/specs/2026-07-13-创意视频校验前置-设计.md`。

## 目标

- 把参数校验从 worker 前置到 `create_task` API 层，校验失败返回 HTTP 400，前端点击生成时即时提示。
- 复用现有 `_validate_params`，不新增重复校验逻辑。
- 前端通过现有 `useToolGeneration` 的 `toast.error(detail)` 显示错误，不改动前端。

## 范围

- 修改 `apps/backend/app/api/v1/endpoints/tasks.py`：新增 `_validate_task_params`，`create_task` 中调用
- 新增后端单测（create_task 校验用例）

## 非范围

- 不扩展前端"条件必填"能力（创意描述不显示 `*` 必填标记，保持现状）
- 不改动 `apps/backend/app/executors/creative_video.py` 的 `_validate_params`
- 不为其他执行器（storybook/ecommerce/marketing）补充 `_validate_params`
- 不修改 worker 的 `autoretry` 配置（可选附带项，默认不纳入）

## 验收标准

- [ ] 文生视频模式（无首帧/尾帧）+ 空 prompt 调用 `create_task` -> 返回 400，detail 含"创意描述必填"
- [ ] 上述场景不创建任务记录、不冻结积分、不提交 Celery
- [ ] 上传首帧 + 空 prompt -> 校验通过，正常创建任务
- [ ] 上传首尾帧 + 空 prompt -> 校验通过
- [ ] 其他工具创建任务不受影响
- [ ] 后端单测通过
- [ ] 手测：创意视频页文生视频模式空 prompt 点生成 -> toast 提示，不进入进度弹窗

## 备注

- 必填规则依据 `docs/api-docs/火山创建视频生成任务 API.md`：文生视频 prompt 必填，图生视频 prompt 可选。
- `_validate_params` 是纯参数校验，不依赖 task_id/db，API 层用占位 task_id 实例化安全。
- `hasattr` 检查保证方案通用：未来其他执行器补充 `_validate_params` 即自动接入。
- 前端 `useToolGeneration.ts` 错误消息读取已修复为 `data.message || data.detail`（后端统一响应错误信息在 `message` 字段，非 FastAPI 默认 `detail`），见 review §8.1。
