# 阶段一执行方案

## 执行总则

1. 采用**主Agent统筹调度 \+ 专业子Agent分工落地**的核心模式，主端仅负责任务派发、进度汇总、成果验收，**严禁编写任何业务代码**，聚焦统筹协调核心职责，确保分工清晰、权责明确。

2. 自动加载\`\.claude/memory/project\_subsystems\.md\`项目记忆文件，精准对齐产品与技术需求，全力攻坚**阶段1核心用户系统**全功能落地，全面覆盖后端API开发、管理端前端开发、用户端前端开发三大核心模块，确保功能无遗漏、需求无偏差。

3. 全程自主研判、选定最优技术实施方案，严格遵循项目既定技术规范与架构标准，无需向用户请示、询问或确认任何需求细节，自主推进开发、测试、交付全流程落地。

4. 所有产出物需严格满足**可编译、可运行、可自测**三大核心要求，全面完成接口测试、功能测试、前后端联调全维度验证，前端产出需额外满足式样校验要求，确保交付成果可直接投入下一阶段使用，无需额外整改。

## 子Agent分工任务

### 1\. 后端API子代理

搭建用户系统后端整体架构，规范完成数据表设计、实体分层、数据访问层与业务逻辑层开发，确保架构清晰、代码可维护；全面实现用户注册、登录、鉴权、权限管理、信息维护全套接口开发，保障接口功能完整、逻辑严谨；统一接口响应格式、全局异常处理、请求参数校验逻辑，提升接口稳定性与易用性；完成服务启动调试、接口自测、单元测试，最终交付可用后端服务、完整接口文档及相关配置文件，确保接口可正常调用、无异常报错、性能达标。

### 2\. 管理端前端子代理

搭建后台管理项目基础框架，结合后台管理系统通用交互逻辑与项目整体技术规范自由发挥，完成用户管理、账号配置、角色权限分配、账号启停管控等核心后台页面开发，确保页面布局合理、操作便捷、风格统一；封装请求工具、配置路由权限拦截，全量对接后端API接口，确保页面数据与后端实时同步、无延迟；完成页面功能调试、多浏览器兼容性测试、编译打包验证及页面式样自测，交付完整可运行的管理端项目包，确保后台操作流畅、功能无缺失、体验符合预期、式样无错乱。

### 3\. 用户端前端子代理

聚焦C端用户场景，严格对照\`docs/design/\`下设计稿、HTML原型，开发用户登录、注册、个人中心、资料编辑等核心页面，确保页面布局、字体、颜色、间距等式样细节与设计一致，优化页面交互逻辑与加载速度；实现登录态管理、路由拦截、前端业务逻辑处理，提升用户交互体验；全量对接用户侧所有后端接口，完成业务流程自测、多终端兼容性测试、打包验证及页面式样自测，确保用户端操作顺畅、数据展示准确、适配各类终端，完全符合设计规范与产品需求、式样无错乱。

### 4\. 全流程测试子代理

全面梳理阶段一全量功能测试用例，精准覆盖接口、页面、业务流程全场景，同步新增页面式样校验相关用例，确保测试无死角；执行接口复测、前后端联调测试、业务流程全链路验证，重点排查字段不一致、权限异常、登录失效、接口调用失败等常见问题，同时通过截图对比、视觉核对，排查页面式样错乱、布局错位等式样问题，同步推动相关子代理完成问题闭环修复与复测，确保问题整改到位；最终出具阶段整体验收测试报告，明确测试结果、问题整改情况及验收结论，为阶段验收提供核心依据。

- 核心目标：确保本次阶段涉及的所有功能完全可用，彻底清除mock数据接口，所有接口均对接真实后端服务，无虚假调用、无数据异常；同时确保前端页面式样无错乱，与设计稿完全一致。

- 测试要求：除基础功能测试、接口测试外，必须采用Playwright框架开展可见模式的自动化测试，测试脚本与用例统一编写至\`apps\\backend\\tests\`目录下，规范命名、便于追溯；通过页面截图对比、模拟真实用户操作，精准验证页面实际表现是否符合预期、业务流程是否顺畅无误，同时重点校验页面式样细节，杜绝隐性bug与式样错乱问题。

- 测试范围：严格限定为本阶段开发涉及的核心用户系统功能及对应前端页面式样，不延伸至非阶段内开发模块，聚焦重点、提升测试效率。

- 测试优先级与执行策略：采用全量覆盖、一次性完成策略，一次性覆盖所有用户系统测试用例（含式样校验用例），涵盖接口测试、E2E自动化测试、业务流程验证，集中开展测试工作，完成后统一汇总问题、推动修复，避免重复测试、提升执行效率。

- 测试报告输出形式：采用验收级标准输出，包含详细测试报告、验收结论页、遗留风险评估、上线建议、复测追踪表，其中需明确页面式样校验测试结果及问题整改情况，确保报告内容全面、逻辑清晰，可直接用于阶段验收。

- 测试方案：采用分层测试策略（推荐），具体架构如下：
        

    - 单元测试层：实现Service层、Security层、工具函数全覆盖，确保核心代码逻辑正确、无基础bug；

    - 接口测试层：对所有用户系统API接口全量覆盖，验证接口响应、参数校验、异常处理等是否符合要求；

    - E2E自动化层：通过Playwright模拟真实用户操作，覆盖核心业务流程，同时校验页面式样细节，验证端到端功能完整性与式样一致性；

    - 手工验证层：对关键业务流程、页面式样进行交叉手工验证，补充自动化测试盲区，确保测试全面性。

## 执行流程

1. 初始化阶段：加载项目记忆文件，明确阶段一功能边界与核心目标，统筹划定各子代理任务范围、时间节点，明确前端式样校验、测试相关要求，并行派发全部开发任务，确保各子代理同步启动、高效推进，避免流程卡顿。

2. 开发阶段：主Agent实时收集各子代理开发进度、代码成果及问题卡点，建立进度同步机制，统一协调前后端联调规范，及时解决跨子代理协作问题，同步关注前端子代理式样开发情况，确保开发节奏一致、衔接顺畅。

3. 测试阶段：所有子代理开发任务完成并通过自测（含前端式样自测）后，统一进入全量测试环节；测试子代理牵头开展分层测试工作，重点落实式样校验测试，跟踪问题整改进度，对整改完成的模块进行复测，确保所有问题闭环、无遗留隐患。

4. 验收交付阶段：测试全部通过后，主Agent汇总完整项目成果、部署说明、测试报告等相关资料，对照阶段目标及式样要求完成全面验收，确认无误后完成阶段一全部功能落地与交付。

## 强制规范

1. 严格遵循项目既定架构标准与代码规范，严禁随意改动技术选型、接口标准及架构设计；确因特殊情况需调整的，需自主验证可行性、评估影响后再落地，确保项目整体一致性、可维护性；前端开发需严格遵循\`docs/design/\`下设计规范，严禁随意修改页面式样。

2. 验收标准：未完成自测（含前端式样自测）、未达到可运行要求、存在明显bug或式样错乱的模块，一律不予验收；各子代理需确保交付模块功能完整、无bug、可正常使用，前端模块式样与设计一致，且符合产出物核心要求。

3. 执行要求：全程静默自主执行，无多余交互，严格按照既定流程、时间节点推进工作，按期完成全部既定功能，杜绝拖延、遗漏、敷衍等情况，确保阶段目标顺利达成；前端子代理需重点把控式样细节，测试子代理需严格落实式样校验测试。
