## 2. 完成情况

### 2.1 `_validate_task_params` 辅助函数

- 位置：`apps/backend/app/api/v1/endpoints/tasks.py`，紧随 `_calculate_task_cost`。
- 逻辑：查询 tool -> `get_executor_class(tool.executor_key or task_in.task_type)` -> `hasattr(executor_class, "_validate_params")` 检查 -> 构造与 worker 一致的 `tool_config`（base_fee/image_fee 等，不局限于创意视频）-> 实例化执行器（占位 task_id）-> 调用 `_validate_params` -> 捕获 `ValueError` 抛 `HTTPException(400, detail=str(e))`。
- `hasattr` 检查保证其他执行器（storybook/ecommerce/marketing，无 `_validate_params`）不受影响，方案通用且向前兼容。
- 传入真实 `tool_config`（而非空 dict），与 worker 实例化一致，使未来依赖配置的 `_validate_params` 也能正确工作。

### 2.2 `create_task` 端点调用

- 在 `_calculate_task_cost` 之后、`TaskService.create_task` 之前插入 `await _validate_task_params(db, task_in)`。
- 校验失败时直接 400，不进入 `create_task`（不创建任务、不冻结积分），不提交 Celery。

### 2.3 不改动项（按 spec 非目标）

- 前端 `DynamicToolForm`、类型定义、`seed_data` 的 `param_schema`：保持现状，创意描述不显示 `*` 必填标记。
- `creative_video.py` 的 `_validate_params`：逻辑已正确，未改动。
- 其他执行器：未补充 `_validate_params`（无必要）。
- worker `autoretry_for=(Exception,)`：未改动（可选附带项，默认不纳入）。

## 8. 审查后修复（2026-07-13）

### 8.1 前端 toast 不显示具体错误消息

- **现象**：用户手测，文生视频模式空 prompt 点生成，toast 显示"创建任务失败，请稍后重试"，未显示后端返回的"文生视频模式下创意描述必填"。
- **根因**：spec §2.2 假设错误--以为 `HTTPException(400, detail=msg)` 返回 FastAPI 默认 `{detail: msg}`。实际后端有全局 `HTTPException` 处理器（`app/main.py:263-272`），把 `exc.detail` 映射到统一响应的 **`message`** 字段，响应体为 `{code, message, error_code, request_id, ...}`，**无 `detail` 字段**。而前端 `useToolGeneration.ts:72` 读 `error.response.data.detail`，取不到，回退默认文案。
- **修复**：`useToolGeneration.ts:72` 改为 `error?.response?.data?.message || error?.response?.data?.detail || ''`，与项目既有正确范式（`apps/frontend-user/src/components/idea/IdeaCard.tsx:74`）一致。
- **影响**：惠及所有走 `useToolGeneration` 的工具（创意视频、绘本、电商、文案、对话模式），不局限于创意视频。前端 `tsc --noEmit` 类型检查 0 错误。
- **与 spec 非目标的关系**：spec §1.3「不改动前端」指不扩展条件必填能力；此处是修复错误消息读取字段（bug），属完成"点击生成时直接提示"目标的必要修复，不涉及必填规则。
