## 8. 审查后修复(2026-07-12)

### 8.1 工具状态切换 422(slug 必填)
- **现象**:工具列表勾选批量 -> 批量下线,返回 422 `slug: Field required`(单条上下线同样受影响)。
- **根因**:`toggle_tool_status`(`admin.py:588`)内部调用 `ToolUpdate(status=status)`,而 `ToolUpdate.slug`(`schemas/tool.py:74`)为**必填** `Field(...)`,导致 `ToolUpdate(status=...)` 创建即校验失败。`ToolUpdate` 其余字段均为 Optional,slug 必填是 Update schema 的反模式 bug。
- **修复**:`ToolUpdate.slug` 改为 `Optional[str] = Field(None, ...)`。`update_tool` service 用 `model_dump(exclude_unset=True)` 只更新传入字段,slug 不传则不更新,安全。
- **验证**:`ToolUpdate(status=1).model_dump(exclude_unset=True)` -> `{'status': 1}`,创建成功。
- **影响**:修复单条/批量上下线;同时修复 `PUT /admin/tools/{id}` 部分更新(不再强制传 slug)。
- **部署**:后端 Python 改动,需重启 uvicorn 生效。

### 8.2 管理端列表看不到下线工具(公开接口强制 status=1)
- **现象**:批量下线后,工具从管理端列表消失;状态下拉筛选(下线/维护中)无效。
- **根因**:管理端 `toolApi.getList` 调公开 `/tools` 接口,而 `ToolService.list_tools`(`tool_service.py:52`)硬编码 `where(Tool.status == 1)` 只返回上线工具;且公开接口不接收 status 参数。
- **修复**:
  - 后端新增 `ToolService.list_tools_admin`(不强制 status=1,支持 status 筛选)
  - 后端新增 `GET /admin/tools`(管理端列表,返回所有状态,支持 status/category_id/search 筛选)
  - 前端 `toolApi.getList` 改调 `/admin/tools`
- **验证**:后端 `py_compile` + `list_tools_admin` import OK;前端 build 通过。
- **部署**:后端需重启 uvicorn。
- **影响**:管理端列表现在显示所有状态工具;状态下拉筛选生效。用户端 `/tools` 不受影响(仍只上线)。
