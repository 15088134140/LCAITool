## 1. 背景与目标

### 1.1 背景

管理后台(`apps/frontend-admin`)共 9 个列表型页面(合计约 4120 行),操作体验"不方便"的根因不是某个页面没做好,而是**整套后台缺少统一的交互抽象层**:

- 9 个页面各自手写搜索、筛选、分页、Modal、空状态、loading,实现互相复制粘贴又不完全一致。
- `@lcaitool/ui` 共享包已是 shadcn/ui 风格(cva + Radix Slot + 语义色 token),但 admin 页面几乎没用上,仍满屏硬编码 hex。
- 存在多处真 bug(统计口径错误、防抖失效、空数据仍渲染分页)。
- 无批量操作、无全局搜索、操作列可访问性差、切换操作无反馈。

### 1.2 目标

- **P1(本任务)**:聚焦列表页**操作效率**,修真 bug、统一搜索/分页行为、补操作反馈与可访问性、加批量操作。不做大范围组件库抽象(留 P0)。
- 遵循 `coding-standards.md`「简单优先」「不引入未被要求的抽象」:共享件仅在「重复 3+ 次且直接服务提效」时才抽。
- 让 9 个列表页的搜索、分页、操作反馈行为一致,减少用户跨页面适应成本。

### 1.3 非目标(留待 P0/P2/P3)

- 不抽 `<DataTable>` / `<FilterBar>` / `<StatusBadge>` / `<Form>`(P0)。
- 不做全局命令面板(⌘K)、侧边栏修复(P2)。
- 不做语义色 token 化、暗色模式(P3)。
- 不重构表单页(`tools/create`、`tools/[id]/edit`)。

### 2.2 真 bug 清单

| # | 位置 | 问题 |
|---|---|---|
| 1 | `orders/List.tsx:248,254,260` | 统计卡片"待支付/已支付/已退款"用 `orders.filter(...)` 基于**当前页**(pageSize=20)计算,与第一张"全部订单"=`total`(全局)口径矛盾,数据被截断误导决策 |
| 2 | `orders/List.tsx:60-62` | `const debouncedSearch = debounce(...)` 写在组件函数体内,每次渲染重建实例,闭包 `timer` 无法跨渲染复用,`clearTimeout` 清不到上一次 timer。debounce 形同虚设,每键仍触发请求(带 300ms 延迟且全部触发) |
| 3 | `reviews:358`、`UserManagement:429`、`orders:350` | 分页器无 `totalPages > 1` 守卫,`total=0` 时仍渲染"共 0 条记录,第 1/1 页"与两个 disabled 箭头 |

> 后端 `get_orders`(`admin.py:414`)仅返回 `{items, total}`,无按状态分组统计,故 bug#1 无法在前端正确修复(需后端接口,留待后续)。

### 2.3 行为不一致清单

1. **搜索触发**:每键即请求(tools/reviews/UserManagement)、debounce 失效(orders)、回车/按钮(ideas/feedback)、客户端过滤(categories)、无搜索(refunds/verifications)——五种模式。
2. **分页样式**:Variant A / Variant B / 无分页,且显示条件不一致。
3. **操作列形态**:纯图标+title / 纯文字 / 图标+文字 三种混用;无 `aria-label`。
4. **切换操作反馈**:上下线(tools)、显示/隐藏(reviews)、启用/禁用(categories、UserManagement)四类**均无确认、无 toast**;删除/退款/审核则有确认 Modal。
5. **错误反馈**:tools 的 `loadTools`/`handleToggleStatus` 失败仅 `console.error` 无 toast;其余 8 页 load 失败有 `toast.error`。
6. **loading 表现**:8 页文字"加载中...",orders 唯一 spinner;无 skeleton。

## 3. 设计方案

### 3.1 共享件抽象边界

| 抽取 | 放置 | 理由 |
|---|---|---|
| `useDebouncedValue<T>` hook | `apps/frontend-admin/src/hooks/useDebouncedValue.ts` | 4 页搜索每键即请求/防抖失效;统一防抖 300ms |
| `<Pagination>` | `packages/ui/src/pagination.tsx`(跨包) | 8 页复制粘贴两套分页器;需加跳页输入+pageSize 选择 |
| `<Modal>` | `packages/ui/src/modal.tsx`(跨包) | 7-8 页逐字重复内联 Modal;确认弹窗基础设施 |
| `<EmptyState>` + 表格 loading 行 | `apps/frontend-admin/src/components/ui/` | 8 页重复"加载中.../暂无数据"模板 |
| **不抽** `<DataTable>`/`<StatusBadge>`/`<FilterBar>` | - | 属 P0,P1 不引入 |

> 跨 `packages/` 修改触发 Superpowers 流程(本 spec 即为其产物)。

### 3.2 交互规范(P1 统一约定)

- **搜索**:服务端搜索统一为防抖 300ms(`useDebouncedValue`);ideas/feedback 现有回车模式保留(非 bug,不强改);categories 客户端过滤不变。
- **分页**:`<Pagination>` 统一支持:页码窗口 + 首末页 + 跳页输入框 + pageSize 选择(10/20/50);`total=0` 时不渲染分页栏。
- **切换操作**(上下线/显示隐藏/启用禁用):改为**即时切换 + 成功/失败 toast**(比现状"无反馈"好且不烦)。删除保留确认 Modal(不可逆)。`undo` 作为可选增强:批次2视 Toast 是否易加 action 决定,不阻塞。
- **操作列**:图标按钮补 `aria-label`;删除等危险操作改「图标+文字」。
- **loading**:表格区用 loading 行(批次1)→ skeleton(批次2)。
- **错误反馈**:所有列表 load/操作失败统一 `toast.error`;成功操作 `toast.success`。

### 3.3 分批策略

| 批次 | 内容 | 风险 |
|---|---|---|
| **批次1** | 修 3 类真 bug;新增 `useDebouncedValue`;新增 `<Pagination>` 并迁移 8 页;tools 失败补 toast;4 页搜索改防抖 | 低-中(分页器迁移面广,但行为等价) |
| **批次2** | 新增 `<Modal>` 迁移 7-8 页;操作列 aria/文字;切换操作 toast;`<EmptyState>`+skeleton;表头 sticky | 中(Modal 迁移需逐页核验 props) |
| **批次3** | tools 批量操作(多选+批量上下架/删除,前端循环);模式稳定后复制到 reviews/UserManagement | 中(批量部分失败处理) |

### 3.4 关键权衡决策

1. **批量操作**:后端 `admin.py` 仅单条 delete/toggle,无批量接口。P1 采用**前端循环调用单条接口 + 进度/结果 toast**,不新增后端接口(避免跨 app + 接口契约变更,扩大范围)。若后续批量量大再补后端批量接口。
2. **orders 统计卡片**:后端无分状态全局统计。P1 **移除三张分状态卡片**(保留"全部订单"=total),正确统计需后端接口,留待后续。
3. **切换操作**:即时切换+toast(可逆、不烦)优于每次确认弹窗;删除保留确认(不可逆)。
4. **搜索统一**:只改 4 个每键/失效页为防抖;ideas/feedback 回车模式保留(减少无必要改动)。
5. **`debounce` 工具函数**:`utils/index.ts:35` 的裸 `debounce` 本身正确,问题在调用方每次渲染重建。P1 用 `useDebouncedValue` hook(内部 `useRef`/`useEffect` 稳定)替代,不修改裸 `debounce`(其他调用方可能依赖)。

## 4. 影响范围与风险

### 4.1 影响文件

- 新增:`packages/ui/src/pagination.tsx`、`packages/ui/src/modal.tsx`(批次2)、`apps/frontend-admin/src/hooks/useDebouncedValue.ts`、`apps/frontend-admin/src/components/ui/EmptyState.tsx`
- 修改:`packages/ui/src/index.ts`(导出)、9 个列表页、`apps/frontend-admin/src/utils/index.ts`(不改动裸 debounce,仅新增 hook 复用)

### 4.2 行为影响

- 搜索/分页/操作反馈行为统一,部分页面交互方式变化(如 tools 搜索由每键即请求改为防抖)。
- 分页器视觉统一(跳页+pageSize),功能增强。
- 不改动任何 API 契约、后端、数据模型。

### 4.3 风险

- **中**:分页器迁移面广(8 页),需逐页核验 `page`/`pageSize`/`total` 字段名与回调一致,避免回归。
- **低**:搜索防抖引入 300ms 延迟,属预期行为变化。
- **低**:Modal 迁移需保留各页特殊 props(tools 的 confirmVariant、verifications/ideas 驳回原因输入)。
