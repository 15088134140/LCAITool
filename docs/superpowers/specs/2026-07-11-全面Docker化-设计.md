# LCAITool Docker 化设计文档

**日期**: 2026-07-11  
**版本**: v1.0  
**状态**: 设计阶段

## 1. 项目背景与目标

### 1.1 背景
LCAITool 是一个前后端分离的 Monorepo 项目，包含：
- Python FastAPI 后端服务
- React + Vite 管理端（frontend-admin）
- Next.js 用户端（frontend-user）
- Celery 异步任务 Worker

目前已有基础的数据库 docker-compose.yml，但缺少完整的应用服务容器化支持。

### 1.2 目标
- **开发环境**: 一键启动配套数据库服务，支持快速验证各服务 Docker 运行状态
- **生产部署**: 各服务独立镜像，支持快速部署和水平扩展
- **环境一致性**: 开发、测试、生产环境配置一致
- **参考 ADSpread 成熟架构**: 复用已验证的 Docker 化最佳实践

### 2.2 服务清单

| 服务名称 | 镜像来源 | 暴露端口 | 说明 |
|---------|---------|---------|------|
| **gateway** | nginx:alpine | 80 | 统一入口，反向代理路由 |
| **postgres** | postgres:16-alpine | 5432 | PostgreSQL 数据库 |
| **redis** | redis:7-alpine | 6379 | Redis 缓存/消息队列 |
| **backend** | 多阶段构建 | 8000 | FastAPI 后端服务 |
| **worker** | 复用 backend 镜像 | - | Celery 异步任务 Worker |
| **frontend-admin** | 多阶段构建 | 80 | React + Vite 管理后台 |
| **frontend-user** | 多阶段构建 | 3000 | Next.js 用户端 SSR |
| **pgadmin** | dpage/pgadmin4 | 5050 | 数据库管理工具（devtools profile） |

### 2.3 网络与存储

- **网络**: 专用 bridge 网络 `lcaitool-network`，服务间网络隔离
- **数据卷**:
  - `postgres_data`: PostgreSQL 数据持久化
  - `redis_data`: Redis 数据持久化
  - `uploads_data`: 后端上传文件存储

## 3. 网关路由设计

### 3.1 路由规则

| 路径 | 目标服务 | 说明 |
|------|---------|------|
| `/` | frontend-admin | React SPA 管理后台 |
| `/user/` | frontend-user | Next.js 用户端 |
| `/api/` | backend:8000 | FastAPI 后端 |
| `/static/` | backend:8000 | 后端静态资源 |
| `/flower/` | worker:5555 | Celery 监控（可选） |

### 3.2 Nginx 配置要点

- 启用 Gzip 压缩
- 配置适当的超时时间（60s）
- 支持 WebSocket 升级（如需）
- 设置安全响应头
- 上传文件大小限制：100MB

## 4. Dockerfile 设计

### 4.1 Backend (Python FastAPI)

**多阶段构建**:
- **Builder 阶段**: python:3.12-slim
  - 安装 gcc 等构建依赖
  - 安装全部 requirements
  - 复制源码

- **Production 阶段**: python:3.12-slim
  - 仅安装运行时依赖
  - 从 builder 复制必要文件
  - 支持 Alembic 数据库迁移
  - 健康检查端点

### 4.2 Frontend Admin (React + Vite)

**多阶段构建**:
- **Builder 阶段**: node:20-alpine
  - 启用 pnpm workspace
  - 安装依赖（workspace 包 + ui 包）
  - 执行 build
- **Production 阶段**: nginx:alpine
  - 复制构建产物
  - 配置 Nginx SPA 路由支持

### 4.3 Frontend User (Next.js)

**多阶段构建**:
- **Builder 阶段**: node:20-alpine
  - 启用 pnpm workspace
  - 安装依赖
  - Next.js build（standalone 模式）
- **Production 阶段**: node:20-alpine
  - 运行 standalone 服务
  - 支持 SSR

### 4.4 Celery Worker

- 复用 backend 镜像
- 通过 `command` 覆盖启动 Celery

## 5. Docker Compose 配置

### 5.1 核心特性

1. **健康检查依赖链**:
   - PostgreSQL 健康 → Backend 启动
   - Redis 健康 → Backend 启动
   - Backend 启动 → 前端服务启动

2. **环境变量支持**:
   - `.env` 文件配置
   - 合理的默认值
   - 敏感信息不提交到代码库

3. **Profile 机制**:
   - `devtools`: pgadmin, flower

4. **资源限制**:
   - 合理的内存/CPU 限制
   - 重启策略: unless-stopped

### 5.2 环境变量

```bash
# Database
DB_PASSWORD=password
POSTGRES_DB=lcaitool
POSTGRES_USER=lcaitool

# Redis
REDIS_PASSWORD=

# Backend
DATABASE_URL=postgresql+asyncpg://...
REDIS_URL=redis://...
SECRET_KEY=...

# PgAdmin
PGADMIN_PASSWORD=admin123
```

## 7. 构建与运行命令

### 开发验证
```bash
# 启动基础服务（数据库 + 缓存）
docker compose up postgres redis -d

# 启动所有服务验证
docker compose up --build

# 启动含开发工具
docker compose up --profile devtools --build
```

### 生产部署
```bash
# 构建镜像
docker compose build

# 后台运行
docker compose up -d

# 数据库迁移
docker compose exec backend alembic upgrade head
```

## 8. 注意事项

1. **Monorepo 处理**: 构建上下文在根目录，需要正确处理 workspace 依赖
2. **.dockerignore**: 排除 node_modules, .venv, .git 等，减小构建上下文
3. **数据备份**: 定期备份 Docker volumes 数据
4. **日志配置**: 配置 Docker 日志轮转，避免磁盘占用过高
5. **安全加固**: 生产环境修改默认密码，启用 TLS
