## 1. 背景与目标

### 1.1 背景

创意视频生成器（slug: `creative-video-generator`，executor_key: `creative-video-generator`）在文生视频模式（未上传首帧/尾帧参考图）下，创意描述（prompt）必填。该校验逻辑存在于执行器 `CreativeVideoExecutor._validate_params`（`apps/backend/app/executors/creative_video.py:88-89`）：

```python
if not first_frame and not last_frame and not prompt:
    raise ValueError("文生视频模式下创意描述必填")
```

但 `_validate_params` 只在 worker 执行 `executor.execute()` 时调用（`creative_video.py:310`），而 `create_task` 端点（`apps/backend/app/api/v1/endpoints/tasks.py:79-112`）不校验参数，直接：

1. 计算费用
2. 创建任务（预冻结积分）
3. 提交 Celery 队列

导致问题：

- 校验失败时任务已入队、积分已冻结，前端只能通过 SSE 看到失败，无法在点击生成时即时提示。
- worker 配置 `autoretry_for=(Exception,)`（`apps/backend/app/workers/tasks.py:247`），`ValueError` 会被无意义重试 3 次，浪费资源并延长用户感知的失败时间。
- 错误日志显示 worker 抛出 `ValueError('文生视频模式下创意描述必填')`，但前端无对应即时反馈。

### 1.2 目标

- 把参数校验从 worker 前置到 `create_task` API 层，校验失败立即返回 HTTP 400，前端点击生成时即时提示。
- 复用现有 `_validate_params`，不新增重复校验逻辑，单一事实源。
- 前端通过现有 `useToolGeneration` 的 `toast.error(detail)` 机制显示错误，不改动前端代码。

### 1.3 非目标

- 不扩展前端"条件必填"能力（不新增 `requiredWhen` 等机制，创意描述不显示 `*` 必填标记，保持现状）。
- 不改动 `creative_video.py` 的 `_validate_params`（逻辑已正确）。
- 不为其他执行器（storybook/ecommerce/marketing）补充 `_validate_params`（当前无条件必填需求）。
- 不修改 worker 的 `autoretry` 配置（可选附带项，默认不纳入）。

## 2. 现状分析

### 2.1 校验链路现状

| 层 | 位置 | 校验 | 问题 |
|---|---|---|---|
| 前端 | `DynamicToolForm.validate()`（DynamicToolForm.tsx:165-217） | 仅校验 `field.required === true` | 创意视频 prompt 的 `required: false`，不校验；前端不扩展条件必填 |
| API | `create_task`（tasks.py:79-112） | 无参数校验 | 直接创建任务+冻结积分+提交 Celery |
| Worker | `executor.execute()` -> `_validate_params`（creative_video.py:310,88） | 条件必填校验 | 校验失败抛 ValueError，被 autoretry 重试，前端无法即时看到 |

### 2.2 错误显示链路（已存在，无需改动）

`useToolGeneration.startGeneration`（`apps/frontend-user/src/components/tool-detail/useToolGeneration.ts:70-91`）的 catch 块：

```typescript
const detail: string = error?.response?.data?.detail || '';
// ...
toast.error(detail || '创建任务失败，请稍后重试');
```

FastAPI `HTTPException(400, detail=msg)` 返回 `{detail: msg}`，axios `error.response.data.detail` 可取到。因此后端返回 400 + detail 时，前端会通过 toast 直接提示。

### 2.3 执行器校验能力盘点

`grep` 确认：仅 `creative_video.py` 定义了 `_validate_params`（`creative_video.py:48`），其他执行器（storybook/ecommerce/marketing）无此方法。`_validate_params` 是纯参数校验，不依赖 `self.task_id`/`self.db`/`self._tool_config`，只用类属性 `SUPPORTED_RATIOS`/`SUPPORTED_RESOLUTIONS`，可在 API 层安全复用。

## 3. 设计方案

### 3.1 API 层提前校验

在 `create_task` 端点中，`_calculate_task_cost` 之后、`TaskService.create_task` 之前，新增 `_validate_task_params` 调用：

1. 查询 tool（复用现有 `select(Tool)` 模式）
2. 用 `get_executor_class(tool.executor_key or task_in.task_type)` 解析执行器类
3. `hasattr(executor_class, "_validate_params")` 检查；无则跳过（保证其他执行器不受影响）
4. 实例化执行器（占位 `task_id`，`_validate_params` 不依赖它）
5. 调用 `executor._validate_params(task_in.input_params or {})`
6. 捕获 `ValueError` -> 抛 `HTTPException(400, detail=str(e))`

### 3.2 设计要点

- **通用复用**：`hasattr` 检查使方案对所有执行器通用。未来其他执行器补充 `_validate_params` 即自动接入 API 层校验，无需再改 `create_task`。
- **单一事实源**：校验逻辑只在 `_validate_params`，API 层仅调用，不重复实现。
- **占位 task_id 安全**：`_validate_params` 不读 `self.task_id`/`self.db`，实例化时用 `uuid.uuid4()` 占位无副作用。
- **不改动前端**：错误显示复用现有 toast 链路。

### 3.3 关键权衡

1. **前端不扩展条件必填**：创意描述的条件必填（仅文生视频模式）由后端 `_validate_params` 控制，前端不显示 `*`、不做校验。优点：最小改动，不引入新 schema 机制；代价：用户填到空 prompt 提交后才看到 toast 提示（而非字段下方即时红星）。用户明确选择此方向。
2. **不修改 worker autoretry**：API 层前置校验后，worker 中 `_validate_params` 的 ValueError 基本不再触发。`autoretry_for=(Exception,)` 对其他 ValueError 的重试问题作为可选附带项，默认不修，避免范围扩大。

## 4. 影响范围与风险

### 4.1 影响文件

- 修改：`apps/backend/app/api/v1/endpoints/tasks.py`（新增 `_validate_task_params`，`create_task` 调用）
- 新增测试：`apps/backend/tests/`（create_task 校验用例）

### 4.2 行为影响

- 创意视频文生视频模式空 prompt：原本创建任务后 worker 失败，现在 create_task 直接 400，不创建任务、不冻结积分、不提交 Celery。
- 其他工具：无 `_validate_params`，`hasattr` 跳过，行为不变。

### 4.3 风险

- **低**：`_validate_params` 在 API 层与 worker 层各调用一次（API 层失败则不进 worker），不影响正确性，仅多一次轻量同步校验。
- **低**：实例化执行器创建 `asyncio.Lock` 等，但仅在工具配置了有 `_validate_params` 的执行器时触发，开销可忽略。

## 5. 验收标准

- [ ] 文生视频模式（无首帧/尾帧）+ 空 prompt 调用 `create_task` -> 返回 400，detail 含"创意描述必填"
- [ ] 上述场景不创建任务记录、不冻结积分、不提交 Celery
- [ ] 上传首帧 + 空 prompt -> 校验通过，正常创建任务
- [ ] 上传首尾帧 + 空 prompt -> 校验通过
- [ ] 其他工具（绘本等）创建任务不受影响
- [ ] 后端单测通过
- [ ] 手测：创意视频页文生视频模式空 prompt 点生成 -> toast 提示"文生视频模式下创意描述必填"，不进入进度弹窗
