# 生成进度弹窗步骤渐进显示设计

## 背景

有声绘本生成弹窗当前在收到第一条结构化进度事件后，会根据 `total_steps` 一次性渲染所有步骤占位，例如“步骤 1”到“步骤 6”。用户期望步骤不要提前全部展示，而是执行到哪一步再显示哪一步。

## 目标

- 初始打开弹窗且尚处于准备阶段时，不展示进度条、百分比、步骤计数或未来步骤占位。
- 收到当前步骤进度后，只显示当前步骤以及已发生的历史步骤。
- 进入下一步时，上一阶段自动标记完成，新阶段逐个出现。
- 第一条真实进度到达后，顶部总步骤计数再显示出来，例如 `步骤 1/6`，不影响整体进度百分比。
- 不改后端 SSE 数据结构，不影响 `step_index`、`total_steps`、`step_status` 的含义。

## 非目标

- 不调整后端执行器步骤数量和进度区间。
- 不改变任务日志、成果生成、取消生成、下载成果等流程。
- 不为不同工具新增单独的进度弹窗配置开关。

## 方案

采用前端最小改动方案，只修改 `apps/frontend-user/src/components/tool-detail/ProgressModal.tsx` 的步骤数组更新逻辑。

当前逻辑收到 `total_steps` 后会补齐全部步骤：

```ts
while (next.length < totalStepsVal) {
  next.push({ name: `步骤 ${next.length + 1}`, status: 'pending' });
}
```

新逻辑改为只补齐到当前步骤：

```ts
while (next.length <= stepIndex) {
  next.push({ name: `步骤 ${next.length + 1}`, status: 'pending' });
}
```

随后沿用现有规则：

1. `total_steps` 继续写入 `totalSteps`，用于顶部总数展示。
2. `stepIndex` 之前的步骤标记为 `completed`。
3. 当前步骤使用 `event.progressMessage` 更新名称，并按 `step_status` 设置为 `running` 或 `completed`。
4. 未来步骤不进入 `steps` 数组，因此不会渲染。

## 用户体验

- 刚打开弹窗：显示 loading 图标、标题、准备阶段等待文案、小提示和取消按钮；不显示进度条、百分比、步骤计数或步骤列表。
- 第 1 步事件到达：进度条区域出现，并显示“正在生成故事大纲...”。
- 第 2 步事件到达：第 1 步变为完成态，第 2 步显示运行态。
- 后续步骤以同样方式逐个出现。
- 完成后已显示的步骤统一变为完成态，并展示成果区域。

## 错误处理

保持现有错误处理逻辑：

- 任务失败时，当前 running 步骤标记为 failed。
- 如果尚未出现任何步骤，则不额外生成未来占位。
- 取消生成仍关闭弹窗并调用取消接口。

## 测试建议

- 单元或组件逻辑验证：模拟 `step_index=0,total_steps=6` 后仅有 1 个步骤。
- 模拟 `step_index=1,total_steps=6` 后仅有 2 个步骤，且第 1 个为 completed。
- 手动验证有声绘本生成弹窗准备阶段不展示进度条、百分比、步骤计数或“步骤 1～6”的占位列表。
